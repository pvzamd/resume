**Main work:**
- Build large, fast, accessible web apps in React, Angular or Vue, with TypeScript, from
  wireframes and designs to pixel-perfect, responsive UI.
- Build reusable component libraries and design-token systems (type, colour, spacing,
  theming).

- Practical use of AI coding tools. An LLM-API integration is "a strong plus".

**Preferred:**
- Storybook; AEM or another CMS; Vite or Webpack; micro-frontends; Node.js; Figma.
- AI/LLM apps; WebSockets or SSE; D3 or other data viz; CI/CD; legacy migrations.

## Gaps to be ready for in interviews

- **GraphQL:** nothing in the notes. Say REST only, and talk about the service layer and
  the token handling.
- **Named test frameworks:** the posting names Jest, Playwright, Cypress and Testing
  Library. You have Vitest, the 170-assertion suites run against the built package, and
  the headless-Chrome harness. Say that honestly.
- **LLM-API integration:** none on the resume, and the posting calls it a strong plus.
  If the support chat's backend is LLM-based, add that to its bullet.
- **State management:** Pinia, and the chat library's provide/inject store. Nothing on
  Redux.
- **Design tokens at enterprise scale:** what you have is a small shared component set
  and Tailwind 4 theme tokens. Don't overstate it.
- **WCAG:** it's in Skills. Be ready on the 2.x AA basics: contrast, focus visible,
  keyboard, labels and errors.
- **Storybook, AEM, micro-frontends:** none. The headless WordPress is the CMS answer,
  and the embeddable chat library is the closest thing to a micro-frontend.
